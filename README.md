## 🧠 What is Rubber Duck Debugging?

**Rubber Duck Debugging** is a debugging technique where a programmer explains their code and reasoning **out loud to an object**, traditionally a rubber duck.

The idea is simple:

> If you can explain exactly what your code is doing, you are much more likely to notice when it isn't doing what you think it is.

You don't need another programmer.

You don't need someone to immediately give you the answer.

Sometimes you just need a duck.

---

## 🦆 Why a Rubber Duck?

The technique became famous through *The Pragmatic Programmer*, where a programmer carries a rubber duck and explains his code to it line by line.

The duck doesn't interrupt.

It doesn't judge.

It doesn't suggest Stack Overflow links.

It just listens.

And while explaining the problem, the programmer often discovers the bug themselves.

## 🔍 Why does it work?

When debugging normally, it's easy to think:

> "I know what this code does."

But when you have to **explain every step**, assumptions become visible.

For example:

```text
"First this variable gets the value..."

"Then this function changes it..."

"Then this condition checks..."

"Then..."

"...wait."

🦆
```

That's usually the moment the bug reveals itself.

The duck didn't find the problem.

**Explaining the problem did.**

---

## 🧩 The Technique

### 01 — Find the problem

Something isn't behaving the way you expected.

### 02 — Grab the duck

Your completely qualified debugging specialist.

### 03 — Explain

Describe what the code is supposed to do, step by step.

### 04 — Question your assumptions

Compare what you *think* happens with what the code *actually* does.

### 05 — Find the bug

Eventually you'll probably say:

> "Oh..."

And there it is.

### 06 — Fix it

The duck gets absolutely no credit.

## 🛠️ Tools still matter

Rubber Duck Debugging isn't a replacement for actual debugging tools.

I still use things like:

* Debuggers
* Breakpoints
* Logs
* Unit tests
* Stack traces
* Code analysis
* Network analysis

The duck is simply another tool — one that helps with the **reasoning behind the debugging process**.
